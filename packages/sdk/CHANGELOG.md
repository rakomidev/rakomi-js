## 0.5.0 — 2026-09-07

- `AuthError` (the shared error type returned by `@rakomi/react` and `@rakomi/react-native`'s sign-in, sign-up, magic-link, email-OTP, MFA, password-reset, and profile calls) now carries an optional `requestId` — the same per-request correlation id the API logs and returns via `X-Request-Id` — when the failed call's response provided one. Hand it back to Rakomi support to correlate a caught error with a server-side log line. Additive and absent (never fabricated) when the server did not emit one; no existing `AuthError` variant changes shape otherwise.
- Every error a caught `AuthzClient`/`AgentsClient`/`LinkClient`/`CredentialsClient`/CIBA-helper call returns now carries the server's per-request correlation id (`request_id`) when the response provided one — as `SdkError.request_id` for the `VerifyResult`-returning methods, and as `VcSdkError.requestId` / `CibaError.requestId` (and its subclasses) for the two that throw. This is the same id the API logs and returns via `X-Request-Id`, so a caught error can be handed back to Rakomi support for log correlation without the caller having to separately capture response headers. The field is additive and absent (never fabricated) when the server did not emit one — no existing error shape changes. One shared parser (`internal/request-id.ts`) reads both envelope shapes the API uses: the RFC 9457 top-level `request_id` on `/v1/*` routes, and the legacy nested `{ error: { request_id } }` envelope on non-`/v1/` routes (AuthZEN, `/oauth/*`).
